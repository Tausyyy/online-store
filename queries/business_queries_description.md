# Бизнес-запросы для интернет-магазина

---

## Запрос 1 — История заказов покупателя

### Бизнес-вопрос

Какие товары и в каком количестве покупал конкретный клиент?

### Параметры запроса

| Параметр      | Описание                                                                |
| ------------- | ----------------------------------------------------------------------- |
| `customer_id` | Идентификатор покупателя. В текущем запросе используется значение `15`. |

### Результат

Запрос соединяет пять таблиц (`customers`, `orders`, `order_items`, `sku`,
`products`). Для покупателя 15 возвращается 410 строк (значение сверено с
независимым подсчётом в `checks/verify.sql`).

| Столбец                         | Содержание                                  |
| ------------------------------- | ------------------------------------------- |
| `customer_id`, `email`          | покупатель                                  |
| `order_id`, `created_at`        | заказ и дата его создания                   |
| `product_name`, `size`, `color` | товар и вариант                             |
| `quantity`, `fixed_price`       | количество и цена, зафиксированная в заказе |

## Запрос 2 — Самые продаваемые товары

### Бизнес-вопрос

Какие товары имеют наибольший объём продаж среди доставленных заказов?

### Параметры запроса

| Параметр | Описание                                              |
| -------- | ----------------------------------------------------- |
| `status` | Учитываются только доставленные заказы (`delivered`). |
| `LIMIT`  | Максимальное количество товаров в результате: 10.     |

### Результат

10 строк в порядке убывания продаж: идентификатор товара, название и суммарное
количество проданных единиц (`total_sold`). У нескольких товаров продажи могут
совпадать, поэтому порядок среди них может отличаться.

## Запрос 3 — Выручка по категориям товаров

### Бизнес-вопрос

Какие категории товаров приносят магазину больше всего выручки?

### Параметры запроса

| Параметр | Описание                                              |
| -------- | ----------------------------------------------------- |
| `status` | Учитываются только доставленные заказы (`delivered`). |

Выручка рассчитывается как сумма произведений количества проданных единиц на
зафиксированную цену товара в заказе.

### Результат

По одной строке на категорию в порядке убывания выручки. Сумма по всем
категориям — 622 078 210.00 (сверена с независимым подсчётом в
`checks/verify.sql`).

## Запрос 4 — Постоянные покупатели

### Бизнес-вопрос

Какие клиенты сделали пять или более заказов?

### Параметры запроса

| Параметр     | Описание                                                                        |
| ------------ | ------------------------------------------------------------------------------- |
| `min_orders` | Минимальное количество заказов: 5. В текущем запросе используется значение `5`. |

### Пример результата

Запрос возвращает 798 клиентов из 1003. Несколько строк:

| ID клиента | Email                          | Количество заказов |
| ---------: | ------------------------------ | -----------------: |
|         22 | gdev_customer_19@example.test  |                 32 |
|         86 | gdev_customer_83@example.test  |                 16 |
|        313 | gdev_customer_310@example.test |                 11 |

Используется `GROUP BY` для группировки заказов по клиентам и `COUNT` для
подсчёта заказов.

Условие `HAVING COUNT(o.order_id) >= 5` отбирает группы, в которых количество
заказов не меньше пяти. `HAVING` применяется после группировки, поскольку
условие зависит от агрегатного значения.

## Запрос 5 — Товары с низким остатком

### Бизнес-вопрос

Какие доступные для продажи варианты товаров необходимо пополнить на складе?

### Параметры запроса

| Параметр          | Описание                                                                                                       |
| ----------------- | -------------------------------------------------------------------------------------------------------------- |
| `stock_threshold` | Порог остатка: 10 единиц. В текущем запросе используется условие `stock_quantity > 0 AND stock_quantity < 10`. |
| `status`          | Учитываются только варианты товаров со статусом `on_sale`.                                                     |

### Пример результата

Запрос возвращает 10 строк: по два варианта (S и M) у пяти товаров.

| Товар            | Размер | Цвет  | Остаток |
| ---------------- | ------ | ----- | ------: |
| gdev_product_1   | S      | white |       2 |
| gdev_product_1   | M      | blue  |       2 |
| gdev_product_101 | S      | white |       3 |
| gdev_product_101 | M      | blue  |       3 |
| gdev_product_201 | S      | white |       4 |
| gdev_product_201 | M      | blue  |       4 |
| gdev_product_301 | S      | white |       5 |
| gdev_product_301 | M      | blue  |       5 |
| gdev_product_401 | S      | white |       6 |
| gdev_product_401 | M      | blue  |       6 |

Запрос соединяет таблицы `products` и `sku`. Условия
`stock_quantity > 0 AND stock_quantity < 10` выбирают только варианты с остатком
от 1 до 9 единиц.

Дополнительное условие `s.status = 'on_sale'` исключает варианты, которые не
доступны для продажи, например архивные и черновые SKU. Порядок строк с
одинаковым остатком может различаться.

Дефицитные варианты создаёт генератор данных
(`scripts/data_generator/generate_data.sql`): они не участвуют в заказах и
корзинах, поэтому их остаток остаётся малым.
