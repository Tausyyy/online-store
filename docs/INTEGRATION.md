
# Интеграция PostgreSQL и MongoDB

## 1. Назначение

Данный документ описывает интеграцию результатов лабораторной работы, выполненной пятью участниками команды.

Цель интеграции — объединить реляционную и документную модели данных, определить границы ответственности каждой СУБД и исключить необоснованное дублирование информации.

В проекте используются PostgreSQL и MongoDB.

## 2. Общая структура проекта

Проект разделён на несколько функциональных частей:

| Компонент | Назначение |
|---|---|
| PostgreSQL | Основная реляционная база данных интернет-магазина |
| SQL Analytics | Аналитические запросы к PostgreSQL |
| MongoDB Model | Проектирование документной модели |
| MongoDB Operations | CRUD-операции и валидация документов |
| Documentation | Документация и результаты экспериментов |

## 3. Распределение ответственности между СУБД

### 3.1. PostgreSQL

PostgreSQL используется для хранения основных бизнес-данных интернет-магазина:

- customers — покупатели;
- categories — категории товаров;
- products — товары;
- sku — варианты товаров;
- carts — корзины;
- cart_items — позиции корзин;
- orders — заказы;
- order_items — позиции заказов.

PostgreSQL является источником истины для перечисленных сущностей.

Реляционная модель обеспечивает связи между таблицами, ссылочную целостность и выполнение транзакционных операций.

### 3.2. MongoDB

MongoDB используется для хранения дополнительной информации:

| Коллекция | Назначение |
|---|---|
| product_content | Дополнительный контент карточек товаров |
| product_reviews | Отзывы покупателей |
| product_questions | Вопросы и ответы |
| product_showcases | Подборки товаров |

MongoDB используется для хранения документов с вложенными объектами, массивами и дополнительными данными.

## 4. Взаимодействие между базами данных

Связь между PostgreSQL и MongoDB осуществляется посредством идентификаторов.

В документах MongoDB используются поля:

- productId — идентификатор товара;
- customerId — идентификатор покупателя.

Значения этих полей соответствуют идентификаторам BIGINT в PostgreSQL и хранятся в MongoDB в виде строк.

Между PostgreSQL и MongoDB отсутствуют общие внешние ключи. Поэтому проверка существования связанных товаров и покупателей должна выполняться на уровне приложения.

## 5. Проверка отсутствия дублирования данных

При интеграции используется принцип разделения ответственности.

PostgreSQL хранит основные сведения о товарах, покупателях, заказах и других бизнес-сущностях.

MongoDB хранит дополнительный контент, отзывы, вопросы и подборки товаров.

Например, название, базовое описание и цена товара относятся к PostgreSQL, а дополнительные характеристики, теги и галерея изображений могут храниться в MongoDB.

Таким образом, базы данных не являются независимыми копиями друг друга.

## 6. Интеграция аналитических запросов

Аналитические запросы участника 1 выполняются непосредственно в PostgreSQL.

Каталог содержит восемь SQL-запросов, которые позволяют:

- анализировать покупки клиентов;
- рассчитывать продажи по категориям;
- формировать рейтинги товаров;
- сравнивать расходы покупателей;
- сравнивать последовательные заказы с помощью LAG;
- рассчитывать накопительную выручку;
- находить покупателей с расходами выше среднего;
- анализировать долю товаров в общей выручке.

Для аналитики используются данные реляционной модели PostgreSQL.

MongoDB не дублирует эти аналитические запросы, поскольку отвечает за другую область данных.

## 7. Интеграция MongoDB

Документная модель включает четыре коллекции.

Реализованы следующие типы связей:

- 1:N — один товар может иметь несколько отзывов;
- 1:N — один товар может иметь несколько вопросов;
- M:N — подборки могут содержать несколько товаров, а один товар может входить в разные подборки.

Также используются вложенные структуры (embedding) и ссылки между документами (reference).

Для контроля структуры документов применяется JSON Schema Validation.

## 8. Результат интеграции

В результате работы пяти участников сформированы следующие компоненты:

1. Реляционная модель PostgreSQL.
2. Каталог аналитических SQL-запросов.
3. Документация по распределению и владению данными.
4. Модель коллекций MongoDB.
5. CRUD-операции и валидация документов.
6. Интеграционная документация и сравнение способов хранения данных.

Разделение PostgreSQL и MongoDB позволяет использовать преимущества обеих моделей без необоснованного повторения одних и тех же данных.

## 9. Заключение

PostgreSQL отвечает за основные бизнес-данные интернет-магазина и аналитические операции.

MongoDB отвечает за дополнительную документную информацию, отзывы, вопросы и подборки товаров.

Каждая СУБД выполняет собственную функцию в общей архитектуре проекта.

Интеграция обеспечивает согласованное использование результатов всех участников лабораторной работы.
