
# Сравнение JSONB в PostgreSQL и MongoDB

## 1. Цель сравнения

Цель сравнения — определить, какой способ хранения лучше подходит для дополнительного контента карточки товара интернет-магазина.

Рассматриваются два варианта:

1. Хранение дополнительной информации в поле JSONB таблицы PostgreSQL.
2. Хранение дополнительной информации в отдельной коллекции MongoDB.

Для сравнения используется один и тот же сценарий: хранение характеристик, тегов и галереи изображений товара.

## 2. Сценарий хранения данных

Дополнительный контент карточки товара может включать:

- дополнительные характеристики;
- теги;
- галерею изображений;
- дополнительные описания;
- динамические параметры товара.

Такие данные могут иметь разную структуру в зависимости от категории товара.

Например, для футболки можно хранить материал и размер, а для обуви — материал подошвы и тип застёжки.

## 3. Вариант 1. PostgreSQL JSONB

В PostgreSQL дополнительную информацию можно хранить непосредственно в таблице products в отдельном поле JSONB.

Пример структуры:

```sql
CREATE TABLE products (
    product_id BIGSERIAL PRIMARY KEY,
    name VARCHAR(255) NOT NULL,
    description TEXT,
    additional_content JSONB
);
```

Пример данных:

```sql
INSERT INTO products (
    name,
    additional_content
)
VALUES (
    'Футболка Basic',
    '{
        "attributes": {
            "material": "cotton",
            "color": "black"
        },
        "tags": ["basic", "casual"],
        "gallery": [
            "front.jpg",
            "back.jpg"
        ]
    }'
);
```

### Преимущества JSONB

- Данные хранятся в одной СУБД.
- Не требуется отдельное подключение к MongoDB.
- Можно выполнять запросы по вложенным полям.
- Поддерживается индексация JSONB.
- Сохраняется возможность использовать SQL и реляционные связи.

### Недостатки JSONB

- Дополнительная информация хранится внутри реляционной записи.
- При сложной структуре JSON становится труднее сопровождать.
- Отдельное управление дополнительными документами менее удобно.
- Изменение JSONB-поля может приводить к обновлению строки таблицы.

## 4. Вариант 2. MongoDB

В MongoDB дополнительная информация хранится в отдельной коллекции product_content.

Пример документа:

```javascript
{
    productId: "101",
    title: "Футболка Basic",
    attributes: {
        material: "cotton",
        color: "black"
    },
    tags: ["basic", "casual"],
    gallery: [
        "front.jpg",
        "back.jpg"
    ],
    schemaVersion: 1
}
```

### Преимущества MongoDB

- Гибкая структура документов.
- Поддержка вложенных объектов и массивов.
- Возможность независимо обновлять дополнительный контент.
- Удобная работа с документами различной структуры.
- Возможность применять валидацию документов через JSON Schema.

### Недостатки MongoDB

- Требуется отдельное подключение к базе данных.
- Нет общих внешних ключей с PostgreSQL.
- Необходимо контролировать соответствие идентификаторов.
- При работе с данными обеих СУБД требуется дополнительная логика приложения.

## 5. Сравнительная таблица

| Критерий | PostgreSQL JSONB | MongoDB |
|---|---|---|
| Структура данных | JSON внутри таблицы | Отдельные документы |
| Гибкость структуры | Высокая | Высокая |
| Вложенные объекты | Поддерживаются | Поддерживаются |
| Индексация | GIN и другие индексы | Индексы по полям документов |
| Связь с PostgreSQL | Нативная | Через идентификаторы |
| Независимое обновление | Обновление поля записи | Обновление документа |
| Валидация структуры | Ограничения и проверки SQL | JSON Schema Validation |
| Отдельное управление документами | Менее удобно | Удобно |

## 6. Сравнение операций

### Чтение

В PostgreSQL данные извлекаются с помощью SQL-запросов и операторов JSONB.

В MongoDB документ можно получить по productId с помощью findOne.

### Обновление

В PostgreSQL для изменения дополнительной информации используется UPDATE с операторами JSONB.

В MongoDB для изменения отдельных полей применяется updateOne с операторами $set и другими операторами обновления.

### Масштабирование структуры

В PostgreSQL можно изменять структуру JSONB без изменения набора обычных столбцов таблицы.

В MongoDB можно хранить документы с разным набором полей в одной коллекции при соблюдении установленных правил валидации.

## 7. Выбор для проекта

В рамках проекта используется MongoDB для хранения дополнительного контента карточек товаров в коллекции product_content.

Такой подход выбран потому, что дополнительная информация рассматривается как самостоятельный документ, который может содержать вложенные характеристики, теги и галерею изображений.

Основные сведения о товаре продолжают храниться в PostgreSQL.

JSONB остаётся альтернативным вариантом для хранения небольших динамических данных, которые тесно связаны с реляционной записью и не требуют отдельного управления.

## 8. Вывод

Оба подхода позволяют хранить полуструктурированные данные.

PostgreSQL JSONB удобен, когда дополнительная информация тесно связана с основной реляционной записью и должна обрабатываться в рамках одной СУБД.

MongoDB удобнее, когда документы имеют самостоятельную структуру и требуют независимого чтения, обновления и валидации.

Для рассматриваемого сценария в проекте выбран вариант с MongoDB.
