# Сравнение JSONB и MongoDB

## 1. Сценарий

В интернет-магазине товары могут иметь разные характеристики. Например, для одежды важны материал и длина рукава, для обуви — материал верха и тип подошвы.

Рассмотрим два способа хранения таких характеристик.

## 2. Вариант PostgreSQL — JSONB

Характеристики можно хранить в поле JSONB таблицы товаров.

```sql
CREATE TABLE products (
    product_id BIGINT PRIMARY KEY,
    name VARCHAR(200),
    attributes JSONB
);
```

Пример записи:

```sql
INSERT INTO products (product_id, name, attributes)
VALUES (
    1,
    'Футболка',
    '{"material": "cotton", "sleeve": "short", "color": "black"}'
);
```

Поиск товаров из хлопка:

```sql
SELECT *
FROM products
WHERE attributes ->> 'material' = 'cotton';
```

В этом варианте характеристики хранятся в одной таблице вместе с товаром. Для поиска по JSONB можно использовать соответствующие операторы и индексы PostgreSQL.

## 3. Вариант MongoDB — отдельная коллекция

В MongoDB характеристики можно хранить в отдельной коллекции `product_attributes`.

Пример документа:

```javascript
{
    product_id: UUID("..."),
    attributes: {
        material: "cotton",
        sleeve: "short",
        color: "black"
    }
}
```

Поиск товаров из хлопка:

```javascript
db.product_attributes.find({
    "attributes.material": "cotton"
});
```

В таком варианте документ с характеристиками связан с товаром через `product_id`. Чтобы получить полную информацию о товаре, может понадобиться дополнительный запрос или агрегирование.

## 4. Сравнение

| Критерий | PostgreSQL JSONB | MongoDB, отдельная коллекция |
|---|---|---|
| Хранение | Поле JSONB в строке таблицы | Отдельный документ |
| Разные наборы характеристик | Поддерживаются | Поддерживаются |
| Получение товара с характеристиками | Обычно одним запросом к таблице | Может потребоваться дополнительный запрос |
| Поиск по характеристикам | Операторы JSONB и индексы | Запросы по полям документа и индексы |
| Связь с товаром | Через строку таблицы | Через `product_id` |

## 5. Выбор для нашего проекта

В архитектуре интернет-магазина характеристики хранятся в поле `attributes` документа коллекции `products` в MongoDB. Они находятся непосредственно в документе товара, потому что обычно читаются вместе с его названием, описанием и брендом.

Отдельная коллекция `product_attributes` приведена здесь как альтернативный вариант для сравнения. В принятой модели проекта она не требуется.

JSONB тоже подходит для хранения характеристик с разной структурой. Однако в нашем проекте каталог отведён MongoDB, а PostgreSQL используется для покупателей, корзин и заказов.

## 6. Вывод

Оба варианта позволяют хранить характеристики товаров с разным набором полей. JSONB удобен, если характеристики нужно хранить рядом с реляционными данными в PostgreSQL. MongoDB подходит для выбранной в проекте документной модели каталога.

Для нашего проекта оставляем характеристики внутри документов `products` в поле `attributes`.
