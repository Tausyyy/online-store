# Архитектура хранения данных PostgreSQL и MongoDB

## 1. Назначение документа

Документ описывает целевую архитектуру хранения данных 
интернет-магазина с использованием
PostgreSQL и MongoDB.

Документ определяет назначение каждой СУБД, структуру хранимых данных, 
связи между сущностями и распределение ответственности между системами хранения.

Распределение данных и источники истины подробно описаны
в документе `data_ownership.md`.

## 2. Общая архитектура

В проектируемой архитектуре используются две независимые СУБД:

**PostgreSQL**

Предназначена для хранения структурированных данных,
между которыми существуют реляционные связи:

- покупатели;
- корзины;
- позиции корзин;
- заказы;
- позиции заказов.

**MongoDB**

Предназначена для хранения каталога товаров:

- категории;
- основные сведения о товарах;
- характеристики товаров;
- варианты SKU.

Такое разделение позволяет использовать преимущества
обеих моделей хранения данных:

- реляционную модель PostgreSQL для связанных сущностей
  и транзакционных операций;
- документную модель MongoDB для каталога с гибкой
  структурой характеристик.

## 3. Логическая структура данных

### 3.1. Структура MongoDB

Для хранения каталога предусматриваются три коллекции.

**categories**

Содержит категории товаров.

Основные данные:
- `_id` — идентификатор категории;
- `name` — название;
- `description` — описание.

**products**

Содержит основные сведения о товарах.

Основные данные:
- `_id` — идентификатор товара;
- `name` — название;
- `description` — описание;
- `brand` — производитель или бренд;
- `category_id` — идентификатор категории;
- `attributes` — вложенный объект характеристик;
- `status` — состояние публикации.

**skus**

Содержит отдельные варианты товаров.

Основные данные:
- `_id` — идентификатор варианта;
- `product_id` — идентификатор родительского товара;
- `sku_code` — артикул;
- `size` — размер;
- `color` — цвет;
- `price` — актуальная цена;
- `stock` — остаток;
- `status` — состояние варианта.

### 3.2. Связи внутри MongoDB

Между коллекциями предусматриваются следующие связи:

1. `categories` → `products` — связь 1:N.
   Одна категория может содержать множество товаров.
   Идентификатор категории хранится в `products.category_id`.

2. `products` → `skus` — связь 1:N.
   Один товар может иметь несколько вариантов SKU.
   Идентификатор товара хранится в `skus.product_id`.

Характеристики товаров хранятся непосредственно
в документе `products` в виде вложенного объекта `attributes`.

Таким образом, в модели используются два подхода:

- embedding — для характеристик товара;
- reference — для связи категорий, товаров и SKU.

### 3.3. Структура PostgreSQL

Для хранения данных в PostgreSQL предусматриваются следующие таблицы:

- `customers` — покупатели;
- `carts` — корзины;
- `cart_items` — позиции корзин;
- `orders` — заказы;
- `order_items` — позиции заказов.

Таблицы связываются между собой реляционными отношениями
с использованием первичных и внешних ключей.

Для связи с MongoDB используются UUID документов SKU,
которые хранятся в полях `sku_id` таблиц `cart_items`
и `order_items`.

Эти идентификаторы не являются обычными внешними ключами,
поскольку соответствующие документы находятся в другой СУБД.
