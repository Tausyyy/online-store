# Инструкция по резервному копированию и восстановлению PostgreSQL

## 1. Назначение

Скрипт `backups/backup_restore.sh` автоматизирует резервное копирование базы данных интернет-магазина и проверку восстановления из резервной копии.

В рамках проверки используются два отдельных сервиса:
- `db` — исходная база данных `online_store`;
- `restore` — отдельный экземпляр PostgreSQL для восстановления.

Исходная база данных не изменяется в процессе восстановления.

## 2. Используемые компоненты

- Docker Compose.
- PostgreSQL 18.
- `pg_dump` — создание резервной копии.
- `pg_restore` — восстановление резервной копии.
- `psql` — проверка данных и ограничений.

Сервис `restore` запускается через профиль `restore` и использует отдельный Docker volume.

Параметры сервиса восстановления:
- База данных: `online_store_restore`.
- Пользователь: `postgres`.
- Порт: `55434`.
- Docker volume: `sprint04_restore_data`.
- Docker network: `sprint04_database_network`.

## 3. Настройка окружения

В корне проекта должен находиться файл `.env`.

Пример его содержимого:

```dotenv
POSTGRES_ADMIN_USER=postgres
RESTORE_DB=online_store_restore
RESTORE_ADMIN_PASSWORD=your_password
RESTORE_PORT=55434
```

`RESTORE_ADMIN_PASSWORD` необходимо заменить на собственный пароль.

Файл `.env` добавлен в `.gitignore`, поэтому локальные параметры подключения не должны попадать в Git.

## 4. Запуск резервного копирования и восстановления

Перейти в корневую директорию проекта:

```bash
cd ~/online-store
```

При необходимости выдать скрипту права на выполнение:

```bash
chmod +x backups/backup_restore.sh
```

Запустить скрипт:

```bash
./backups/backup_restore.sh
```

Скрипт последовательно выполняет следующие действия:

1. Проверяет доступность исходной базы данных `online_store`.
2. Создаёт резервную копию с помощью `pg_dump` в формате Custom.
3. Проверяет целостность и читаемость архива с помощью `pg_restore -l`.
4. Запускает отдельный сервис `restore`.
5. Удаляет и заново создаёт базу `online_store_restore` на сервисе восстановления.
6. Восстанавливает данные и структуру из резервной копии.
7. Сравнивает количество записей в таблицах исходной и восстановленной баз.
8. Сравнивает количество ограничений в исходной и восстановленной базах.

При обнаружении ошибок или несовпадений скрипт завершает работу с ненулевым кодом возврата.

**Важно:** при повторном запуске скрипт пересоздаёт только базу `online_store_restore` на сервисе `restore`. Исходная база `online_store` не удаляется и не пересоздаётся.

## 5. Результаты резервного копирования

Резервная копия сохраняется в файле:

```text
backups/online_store.dump
```

Файл содержит резервную копию базы данных `online_store` в формате Custom PostgreSQL.

## 6. Проверка результатов восстановления

После восстановления скрипт сравнивает количество записей в девяти таблицах.

| Таблица | Количество записей |
|---|---:|
| cart_items | 1590 |
| carts | 2001 |
| categories | 23 |
| customers | 1003 |
| order_items | 100003 |
| orders | 10002 |
| products | 503 |
| schema_migrations | 1 |
| sku | 2504 |
| **Итого** | **117630** |

Также проверяется количество ограничений в базе данных.

| Тип ограничения | Исходная база | Восстановленная база |
|---|---:|---:|
| CHECK (`c`) | 5 | 5 |
| FOREIGN KEY (`f`) | 8 | 8 |
| NOT NULL (`n`) | 42 | 42 |
| PRIMARY KEY (`p`) | 9 | 9 |
| UNIQUE (`u`) | 3 | 3 |
| **Итого** | **67** | **67** |

Количество записей и ограничений в исходной и восстановленной базах совпадает.

## 7. Файлы с результатами

После выполнения скрипта формируются следующие файлы:

| Файл | Назначение |
|---|---|
| `backups/backup_restore.sh` | Скрипт резервного копирования и восстановления |
| `backups/online_store.dump` | Резервная копия базы данных |
| `backups/backup_restore.txt` | Журнал выполнения скрипта и результаты проверок |

## 8. Итог

Резервное копирование и восстановление базы данных выполнены успешно.

Восстановление проведено в отдельный экземпляр PostgreSQL, без изменения исходной базы данных.

Проверка подтвердила совпадение количества записей во всех девяти таблицах и количества ограничений в исходной и восстановленной базах.
